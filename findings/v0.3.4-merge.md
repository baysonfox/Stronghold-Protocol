# 升级合并记录：v0.3.1 → v0.3.4-dev（同步 upstream/dev + Paper-Yuan 分支盘点）

## 1. 背景与升级目标

本次升级从本地 `v0.3.1`（`581faf16`）跨版本直接同步至官方开发分支 `upstream/dev`（`ef206f09`，涵盖已发布的 `v0.3.2`、`v0.3.3` 以及未发布的 `0.3.4` 全部更新，共计约 689 个上游提交），并将生产环境从 `v0.3.0` 零停机蓝绿升级至最新构建。

本仓库在官方原版主干之上继续维护三项定制能力：
1. **内置 271 款干员时装资产（Fusion Skins）**：172 位干员的 271 套时装骨骼与立绘/头像，100% 走官方 `chars[<charId>].skins` 清单与 `room.skins` 同步管线。
2. **服务器维护公告与禁开局倒计时**：顶部跑马灯 `NoticeBanner`、局内里程碑 Ticker 广播、最后 10 分钟禁建房/禁开局拦截及 `/admin/maintenance` 管理接口。
3. **Caddy 蓝绿零停机部署与实时战况监控**：双容器共享素材目录、活跃/离线挂起对局区分排空、`/healthz` 分布统计及 `/admin/matches`、`/admin/rooms` 接口。

## 3. Paper-Yuan 分支（`v0.3.3-Yuan`）自研内容盘点

按惯例本次仅核查皮肤/语音兼容修复，不合入破坏原版确定性的魔改玩法。经全面审计 `paper/align/0.3.0`（`14760081`），其团队自研的新增模块归纳如下：
1. **大厅「拓展模式」（第三张入口卡 `EXTENSION MODE`）与三大自制玩法**：
   - **超限 / 无限模拟（Overlimit / Infinite）**：无限回合、分段成长曲线、Boss 回合前预警横幅与词条抉择面板（Trait Picker）、解除盟约 999 层上限（如叙拉古无限叠层）、超限盟约弹窗数值高亮分色（`.olb-num`）及局内随时切换 1x/2x 倍速。
   - **湮灭模拟（Annihilation）**：125 棋子池 + 蚀流档位 + 二级主题大厅「功能设置」，将 8 个工坊 Mod（新盟约【罗德岛】【卡兹戴尔】、阿戈尔开局加攻、通讯机核心盟约优先、备战改技能/可卸装备/变形同构体强化/商店盟约偏好）封装为仅在湮灭模拟内生效的模式门开关。
   - **炸惊模拟（ZHAJING）**：移植外部整合包的独立 205 条 `chess_zj_*` 棋库、5 条新盟约 + 21 条盟约覆盖，以及「惊变」抽卡增益系统（我方 99 张五稀有度卡 + 敌方 21 张 + 18 条惊变羁绊）。
2. **12 人联机「三队共抗」模式（`TWELVE_PLAYER_MODE`）**：
   - `3 队 × 4 人` 编制，队内共用卡池、队间独立；每人独立血条，漏怪伤害按全体存活人数 `round3(d/n)` 平摊（残差归末位）；「队内联防 → 观看等待 → 跨队联防」三段状态机与专属 `multiHud`。
3. **皮肤专属语音（Skin Voices）**：
   - 新增 `data/skin-voices.json` 与 `audio.skinVoice{,Jp,En,Kr}` 分支，穿戴带独立配音的典藏/联动皮肤时优先播放皮肤专属语音。
4. **隐藏彩蛋 ARG 解谜页（`public/arg/`）**：
   - 页脚版本号连续点击 5 次进入 5 页萨卡兹铭文密码学/填字解谜页面。
5. **双端独立打包（`android/` + `desktop/`）与旧工坊层（`workshop/`）**：
   - Android 端通过 JNA 嵌入 `libnode.so` 实现纯离线单进程运行；桌面端基于 Electron 提供启动选择页；同时额外保留了 4500+ 行旧版 `pack.json`（manifest v1）兼容层。
   - *注*：其 `handoff/` 文档记录合并 0.3.3 后仍有约 105 条单元测试待清理；而此前在 `v0.3.1` 采纳过的换皮立绘即时刷新已在官方 `0.3.2` `OperatorImage` 内置 `useStore(..., skinsStore)` 原生覆盖，`media.js` 的 `#` 转 `%23` 转义已在我们分支保留。

## 4. 冲突解决、冗余清理与踩坑记录

### 4.1 彻底清理 `v0.2.x` 遗留死代码，100% 对齐官方原生皮肤架构
- **移除无引用的 `data/skins.json` 与 `docs/research/08-skins.json`**：官方自 `0.3.1` 起完全从 `data/assets.json` 的 `chars[<charId>].skins` 读取时装目录；且在 `0.3.2` 引入多版本校验（`test/data-versions.test.js` 与 `versions-default-guard`）后，若 `server/data.js` 的 `DATA_FILES` 继续保留 `'skins'`，会导致加载无 `skins.json` 的历史版本目录报错。本次同步清理了 `server/data.js`、`public/js/main.js`、`public/js/ui/gameComponents.js` 中的 `'skins'` 遗留项。
- **清理 `loadout.js` 与 `loadout.css` 中的旧融合残留**：
  - 上次合并在 `loadout.js` 末尾残留了一处重复且传参错误的 `<${SkinSection} chess=${chess} />`（官方组件签名为 `{ charId }` 且已在上方挂载），同时官方 `OperatorImage` 已原生订阅 `skinsStore`；本次直接对齐 `upstream/dev` 原生 `loadout.js`。
  - 旧融合追加在 `loadout.css` 底部的 102 行垂直小图标 `.lo-skin` 样式会覆盖官方 5 列 1:2 半身像网格与矮屏自适应样式，本次已移除并恢复官方原生样式。
- **对齐官方源码级正则契约测试**：`test/ui/lobby-hub.test.js` 与 `test/ui/version-vote.test.js` 对 `lobby.js`（`AllianceSelect` 末尾属性与 `room.create` 参数缩进）和 `room.js`（`GoButton` 的 `disabled` 表达式）做源码级精确正则匹配。通过保持 `short=${shortScreen}` 结尾并在 `room.js` 将 `if (inCutoff) facts.canStart = false` 汇入 `facts.canStart`，在完整保留维护禁建房/禁开局拦截的同时满足官方源码测试。
- **战斗快照与玩家生成对齐**：`server/sim/battle/players.js` 与 `server/sim/snapshot.js` 均已由官方原生支持 `u.skin` 及召唤物皮肤 `ownerCharId`，直接采用上游实现，避免重复键报错。

### 4.3 素材补齐与两个关键踩坑
1. **坑一：无 `local-fx` 索引机器运行 `fetch-assets.mjs` 会降级技能音效槽位**
   - 现象：官方提交的 `data/assets.json` 是在带有官服提取特效索引（`local-fx`）的机器上生成的，包含了 PR #848 修正的 19 名干员 26 处精确技能音效槽位；若在无 `local-fx` 的机器上直接采纳 `fetch-assets.mjs` 重建的清单，会退回按文件名字母匹配并丢失 28 个技能音效引用。
   - 解决：仅用 `fetch-assets.mjs --add-only --refresh-index` 下载并归一化新增的 1,550 个干员/敌人 Spine、立绘与五语配音，随后恢复 `upstream/dev` 权威 `data/assets.json` 底座，单独从 `ArknightsAssets2@voice` 补齐 28 个技能音效 `.mp3`，最后执行 `node tools/integrate-fusion-assets.mjs --strict` 注入 271 款时装。
2. **坑二：旧提取的 `public/assets/local/spine/enemy/` 残留 `pma: true` 触发 Spine 校验断言**
   - 现象：早期（`0.3.0`）本地提取的 `enemy_1305_mhslim` 与 `enemy_1305_mhslim_2` 的 `.atlas` 带有旧提取器误写的 `pma: true`（图像本身实为 straight RGB），而新版 `tools/assets/local-enemy-spines.json` 已修正为 `pma: false`，导致 `test/assets.test.js` 的客户端加载一致性测试断言失败。
   - 解决：清理上述两个本地提取 `.atlas` 中误标的 `pma: true`，使全量 Spine 加载测试满血通过。
